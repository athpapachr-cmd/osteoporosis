# Explicit stored visit amendments

PO requests editing an existing visit from its beginning, including an old visit captured before the improved Dia prompt. No real visit/task will be amended automatically. Missing checklist data is not a future obligation; installed extraction instruction already enforces that independently of pasted prompt.

## Owner and contract

Reuse EncounterORM._visit_capture_v1, protected chart/context/extract/preview and renderer. Extend with explicit physician amendment GET/POST under exact patient+encounter paths; retain direct PUT immutability. No new tables/grants. Current signed candidate becomes effective revision; append the complete previous signed envelope (excluding nested history), previous date/status and amendment actor/time/request identity to a flat JSON history in the same row. Encounter id/created_at and all earlier snapshots stay unchanged. Status becomes amended, row and patient timestamps advance; all existing chart/brief consumers use current candidate. Read UI labels corrected recording and offers protected read-only previous rendered detail/date. Shared-key actor is honestly shared_clinical_key; staff-cookie presence requires valid clinician, secretary/expired/invalid denied without fallback.

Edit GET returns current candidate, expected token covering encounter date/status/updated_at/signed envelope plus ALL source Pending rows and checkpoint revisions, and only operational noncancelled/nondeleted source bindings as editable task entries. Cancelled/deleted tasks are never copied into the draft; old candidates may retain original historical text. No automatic restoration. New amendment request includes existing valid capture context, immutable patient/encounter in URL, expected token, UUID request id, candidate and parallel optional pending-id bindings. All schemas privately validated (no clinical input echoed), size bounded. Existing candidate/provenance/date/identity validation applies; consistent identity required, only explicit Save mutates. Model extraction remains optional draft-only; clinician edits marked clinician_edit.

## Tasks and atomicity

Unchanged bound candidate task retains its original Pending id and every completion/not-yet/cancellation audit. Compare with current signed candidate item, not mutable operational status. Changed bound task is explicitly shown as replacement: cancel original through the SAME lifecycle cancellation helper, create a NEW unfulfilled row with source=this encounter; never carry completion onto changed meaning. Removed source task is reversibly cancelled through that same helper. New task requires open/awaiting_patient/awaiting_result. Foreign, duplicate, cancelled/deleted/obsolete bindings reject409; omitted cancelled/deleted tasks stay untouched. Re-extraction from pasted text has no inferred binding: show old tasks as proposed removals and new tasks as new for explicit review before Save, avoiding automatic semantic/name matching. UI explains replacements are new open obligations.

Keep source metadata for ALL historical task ids: current pending_ids align exactly with effective candidate.pending; prior flat revision snapshots remain available for source-excerpt fallback for removed/replaced/cancelled tasks. Same source encounter id and signed source predicate remain. No hard deletion or existing permanent-task semantics change.

One transaction: strict actor/auth; row lock encounter and source Pending rows sorted; validate expected full token and capture context, explicit binding diff; atomic encounter updated_at compare-and-swap (SQLite/Postgres) and context consumption; append history/effective candidate, lifecycle cancellation events and new Pending rows; update patient; commit. Any conflict rolls everything back. Existing Pending routes reuse extracted cancellation helper with identical metadata/event/revision semantics. Unique event revisions protect SQLite races; stale observed task status or checkpoints reject rather than overwriting. Retry after lost response uses exact request id + digest of complete request and actor retained in flat history, checked after auth/exact patient but before expired/consumed context; exact replay returns success without further writes, conflicting reuse409. Subsequent amendments keep all request receipts.

## UI

Focused visit has Επεξεργασία επίσκεψης. Reuse transient composer with original date and full structured candidate ready for correction (no model needed), optional paste/re-extract of natural text. All normal editable sections include adding/removing facts/tasks and next contact, including previously empty sections; no raw JSON. Existing pending bindings held only in transient JS map and serialized explicitly. Header clearly says editing this date, Save says Αποθήκευση διορθώσεων, Cancel returns to exact visit. No ordinary New Visit Save/duplicate encounter. Dirty draft/pending busy navigation guards include amendment, prevent reset/switch/late-result/auth repaint; logout clears clinical text. Preview shows clinician fields plus concise kept/new/replaced/removed task review. Save disables fields and close while in flight; errors preserve draft, exact retry safe; stale response does not reset another patient/draft.

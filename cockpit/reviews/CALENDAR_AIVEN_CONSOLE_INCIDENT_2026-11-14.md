# Aiven console execution incident

During database qualification, the Aiven SQL editor unexpectedly restored an earlier query in an existing tab. The attempted metadata query was pasted without first clearing that editor, and Run executed the restored contents. The visible results were `BEGIN`, a `set_config` statement, and an attempted `CREATE TABLE public.clinical_pending_checkpoint_events`, which returned `relation ... already exists`. No later statement or successful CREATE was shown. Do not infer an unobserved COMMIT or a patient-data mutation. A separate, newly created empty query then confirmed database `osteoporosis`, connected user and both existing calendar tables; no patient rows were read. The approved temporary single-address allowlist entry was removed and the original three entries visibly restored. The intended calendar migration was not executed or verified in production. Subsequent SQL must use a newly created empty editor and explicit verification before Run.

On a second user-authorized temporary-access attempt, the console failed to accept input reliably into a new empty editor. No SQL was run in that attempt. The temporary address was removed and the original three allowlist entries visibly restored again. A subsequent harmless input-only probe also failed to populate the editor; no query was executed. The user was asked to bring the Dia/Aiven window to the foreground so the safe input route can be reassessed before any further changes.
